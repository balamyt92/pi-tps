# pi-tps

Честная статистика генерации LLM для [pi](https://github.com/badlogic/pi-mono): скорость генерации, задержка первого токена, диагностика спекулятивного декодирования.

## Установка

### Из git-репозитория

```bash
pi install git:github.com/<user>/pi-tps@v1.0.0
```

Поддерживаются HTTPS и SSH:

```bash
pi install https://github.com/<user>/pi-tps@v1.0.0
pi install git:git@github.com:<user>/pi-tps@v1.0.0
```

### Из локальной папки (для разработки)

```bash
pi install /path/to/pi-tps
```

После установки — `/reload` в сессии или перезапуск pi.

## Что показывает

### Уведомление после каждого хода агента

```
⚡ 29.6 tok/s · TTFT 1.95s · out 300 (текст 300) · 618 симв. · контекст 69 891 · 8.2s · 2 выз.
```

- **⚡ eff tok/s** — главная метрика: output / (отправка запроса → последний токен). Совпадает с реальным временем ожидания ответа (проверено против логов llama.cpp с точностью <5%).
- **TTFT** — время до первого сгенерированного токена.
- **out / текст** — сгенерированные токены; отдельно текстовая часть (без reasoning).
- **контекст** — размер входного контекста последнего вызова.

### Команда `/tps`

Развёрнутая разбивка по каждому LLM-вызову за ход:

```
#1  out 80  in 69 819  eff 23.5 tok/s  (decode 111.4 tok/s)  TTFT 2.64s  20 дельт (~4.00 ток/дельта)  gaps p50 38ms p95 190ms  stop=toolUse
#2  out 220  in 69 891  eff 32.8 tok/s  (decode 40.3 tok/s)  TTFT 1.26s  200 дельт (~1.10 ток/дельта)  gaps p50 38ms p95 47ms  stop=stop
────────────────────────────────────────────────────────────
Итого: out 300 (текст 300 · reasoning 0) · контекст (max) 69 891 · 6.2s генерации
Символы: 618 · 100.0 зн/с
TTFT: avg 1.95s · max 2.64s
Eff TPS: 29.63 tok/s  ← запрос→последний токен (совпадает со стеной сервера)
Decode:  48.57 tok/s  (первый→последний дельта; завышен из-за буфера первой дельты)
~1.57 ток/дельта — похоже на speculative decoding (MTP)
```

- **Eff TPS** — надёжная метрика скорости.
- **Decode TPS** — «чистое» окно генерации; оставлено для диагностики (на коротких ответах систематически завышено из-за буфера первой дельты).
- **gaps p50/p95** — распределение пауз между дельтами. Сильный перекос p95 → берсты доставки.
- **~ток/дельта** — при >1.5 экстеншн помечает вероятное спекулятивное декодирование (MTP и т.п.).
- Сбойные вызовы (`error`/`aborted`) помечаются ❌ и исключаются из итогов.

## Особенности для локального инференса

Клиентский `usage` от локальных серверов (llama.cpp, llama-swap и др.) может расходиться с их внутренними счётчиками, а prompt-caching на стороне сервера не отражается в клиентских полях `cacheRead`. Экстеншн честно сообщает об этом и опирается только на измеримые клиентские тайминги.
